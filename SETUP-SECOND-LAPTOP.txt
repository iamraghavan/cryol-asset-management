CRYOL ASSET MANAGEMENT — SECOND LAPTOP SETUP

GitHub repository
https://github.com/iamraghavan/cryol-asset-management

Install Git and sign in with a GitHub account that can access the repository.
With GitHub CLI, run gh auth login and gh auth setup-git before cloning.
On Windows, use Git Bash for the shell commands below.

    git clone https://github.com/iamraghavan/cryol-asset-management.git
    cd cryol-asset-management

OPTION A — DOCKER COMPOSE

Install Docker Desktop on Windows or macOS, or Docker Engine and the
Compose plugin on Linux. Start Docker and verify docker compose version.
Official instructions: https://docs.docker.com/compose/install/

Use a new database password for this laptop. The example below generates
a URL-safe 64-character hexadecimal password. Run it once in a fresh clone.

    (umask 077; printf 'CRYOL_POSTGRES_PASSWORD=%s\nCRYOL_HTTPS_PORT=8443\n' "$(openssl rand -hex 32)" > .env)
    docker compose build
    docker compose run --rm app cryol-dev-certificate
    docker compose run --rm app cryol-cli migrate
    docker compose run --rm app cryol-cli bootstrap-admin admin
    docker compose up -d --wait

Choose an administrator password of at least 15 characters when prompted.
Use https://localhost:8443. Setup generates a self-signed TLS certificate
for this laptop. To inspect or import the public certificate through your
browser or operating system's local trust settings, export it with:

    docker compose exec -T app cat /var/lib/cryol/tls/server.pem > cryol-local-cert.pem
    curl --cacert cryol-local-cert.pem https://localhost:8443/api/v1/system/readiness

The Docker configuration publishes Cryol on the laptop itself. PostgreSQL
uses an internal Docker network. Cryol data remains in the postgres named
volume. To stop and resume without removing data:

    docker compose down
    docker compose up -d --wait

To update after pulling new code, take a database backup first. Then run:

    docker compose exec -T db pg_dump -U cryol -d cryol -Fc > /path/to/private/cryol-backup.dump
    git pull --ff-only
    docker compose stop app
    docker compose build
    docker compose run --rm app cryol-cli migrate
    docker compose up -d --wait

OPTION B — GITHUB CLONE AND NATIVE POSTGRESQL

1. Install Git, Go 1.26.4 or a compatible newer Go toolchain, Node.js 22.12
   or later with Corepack, and PostgreSQL 17 with command-line tools.

   PostgreSQL installers: https://www.postgresql.org/download/
   Windows: Complete the PostgreSQL installer, record the password for the
   postgres administrator, and start the PostgreSQL service. Add the PostgreSQL
   bin directory to PATH if psql is unavailable in a new Git Bash window.
   macOS and Linux: Start the PostgreSQL service using your installation's
   service manager. Use the administrator role created by your installation.

   Verify the tools and server:

       git --version
       go version
       node --version
       corepack --version
       psql --version
       pg_isready -h 127.0.0.1 -p 5432

2. Clone the repository using the Git commands at the top of this guide.
   From the repository root, open PostgreSQL as an administrator:

       psql -h 127.0.0.1 -p 5432 -U postgres -d postgres

   Replace postgres after -U if your administrator uses another name.
   On Linux installations that use peer authentication for administration,
   open psql with sudo -u postgres psql -d postgres instead. In psql, run:

       CREATE ROLE cryol LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
       \password cryol
       CREATE DATABASE cryol OWNER cryol;
       \q

   At the password prompt, choose a new PostgreSQL password for the cryol
   role. Save it privately. If either the role or database already exists,
   verify its owner and intended use before selecting it for this setup.

3. Test the same TCP login Cryol will use:

       psql -h 127.0.0.1 -p 5432 -U cryol -d cryol -W -c "select current_user, current_database();"

   The result should show cryol in both columns. Copy the environment
   template in the repository root:

       (umask 077; cp .env.example .env)

   Edit .env and set the following values. Replace the password placeholder.
   Percent-encode reserved characters in the password for use in a URL.

       CRYOL_DATABASE_URL='postgres://cryol:REPLACE_WITH_LOCAL_DB_PASSWORD@127.0.0.1:5432/cryol?sslmode=disable'
       CRYOL_HTTP_ADDR=127.0.0.1:8080

   The PostgreSQL password is separate from the password you use to sign
   in to Cryol. Keep .env private. Use sslmode=disable only for a database
   on the same laptop. Leave optional agent and TLS settings empty for
   this local-only setup.

4. Install frontend dependencies, apply migrations, check the schema, and
   create the first Cryol administrator:

       corepack pnpm install --frozen-lockfile
       set -a
       . ./.env
       set +a
       cd apps/server
       go run ./cmd/cryol-cli migrate
       go run ./cmd/cryol-cli schema-check
       go run ./cmd/cryol-cli bootstrap-admin admin
       go run ./cmd/cryol-server

   Choose a Cryol admin password of at least 15 characters. Bootstrap is
   for an empty Cryol installation. Skip it when using a restored database.

5. Open a second terminal at the repository root and start the frontend:

       corepack pnpm --filter @cryol/web dev

   Open http://localhost:5173 and sign in as admin. Verify the backend:

       curl http://127.0.0.1:8080/api/v1/system/readiness

   The readiness endpoint should return {"status":"ready"}. If psql reports
   a connection refusal, check the PostgreSQL service and port. If psql
   rejects the password, resolve the role login before running migrations.

   For an all-in-one native console, run corepack pnpm build at the root and
   set CRYOL_WEB_DIR in .env to the absolute path to apps/web/dist. You can
   use forward slashes in Windows paths. Reload .env from the project root,
   start the Go server, and open http://127.0.0.1:8080.

PostgreSQL references:
https://www.postgresql.org/docs/17/app-psql.html
https://www.postgresql.org/docs/17/sql-createrole.html

ENVIRONMENT FILES AND EXISTING DATA

.env.example is the Git-tracked native template.
.env.docker.example lists Docker variables and example defaults.
.env is private and ignored by Git. Keep one .env configuration per clone.
CRYOL-ENV.local.txt contains original values on the source laptop and is
also ignored. Its paths and LAN address are specific to that laptop.
The TLS private-key contents and the Cryol admin password are separate
from these environment values.

A Git clone transfers code only. A new database starts empty and requires
bootstrap-admin. To move existing users, assets and agents, transfer a
PostgreSQL backup privately, restore it into a new empty destination
database, then apply Cryol migrations. Skip bootstrap for a restored
database. Keep the original installation and its backup until you
verify the new one. LAN agent enrollment also needs a reachable HTTPS
address, a matching certificate and any installer binaries configured
through the agent environment values.
